## Latest server check

Pulled `../notees` to commit `d37ce40a` (main). The server is now a
local-first, operation-log architecture:

- Sync endpoints: `POST /api/relay/batch`, `POST /api/relay/catch-up`,
  `GET /api/relay/snapshot`, `POST /api/relay/snapshot`, `POST /api/relay/compact`,
  `/api/relay/ws/{workspace_id}`.
- Legacy endpoints removed: `/api/nodes/*`, `/api/properties/*`, `/api/sync/*`.
- Envelope: `{id, workspaceId, actorId, hlc:{physical,logical},
  affectedNodeIds[], opType, payload}`.
- Derived state is rebuilt client-side from the immutable operation log.

## Sync compliance — what matches

- **Wire format**: Flutter sends/receives camelCase envelope keys
  (`workspaceId`, `affectedNodeIds`, `opType`, etc.). The server accepts both
  camelCase and snake_case (`populate_by_name`), so this is compatible.
- **Batch push**: `POST /api/relay/batch` body `{"envelopes": [...]}` matches.
  Response keys `saved_count` / `saved_ids` are correctly parsed by
  `RelayBatchResponse`.
- **Catch-up request/response**: now uses snake_case keys (`workspace_id`,
  `after_id`, `next_after_id`, `has_more`, `restore_epoch`) to match the server
  wire format.
- **Snapshot response**: now parses snake_case keys (`snapshot_id`,
  `workspace_id`, `data_base64`, `has_snapshot`, `restore_epoch`) so the SQLite
  snapshot bytes can be restored.
- **HLC ordering**: Flutter and server both order by physical, then logical,
  then envelope id as a tie-breaker.
- **HLC clock semantics**: aligned with the server's `Clock.update`
  implementation (`lib/domain/services/hlc_clock.dart`).
- **Operation payloads**: `node.create`, `node.updateContent`, `node.updateIcon`,
  `node.updateColor`, `node.archive`, `node.restore`, `node.delete`,
  `node.move`, `property.set`, `class.assign`, `class.unassign`,
  `user.favorite.*` use the same field names as the server's derived appliers.
- **System UUIDs**: class and property UUIDs match
  `app/domain/entities/constants.py`.
- **Daily journal UUIDs**: deterministic date UUIDs match the server's
  `generate_day_uuid` format.
- **Write paths**: task creation, quick notes, inbox blocks, journal pages,
  block edits, deletes/restores, archive/restore, icon/color updates, move
  ordering, tag assignment, and property changes are all emitted as relay
  operations and flushed through `SyncV2Service`.
- **Background sync**: `BackgroundSync` / `OfflineSync` call `flush()` and
  `pull()` on lifecycle events.
- **Snapshot binary restore**: `GET /api/relay/snapshot` SQLite bytes are
  decoded and loaded into `node_cache`, `property_value`, and
  `node_child_order` when the snapshot HLC is newer than the local watermark.
- **Archive/restore**: `node.archive` / `node.restore` operations set the
  `isArchived` flag locally and are accepted by the server appliers.
- **Task completion**: `task.recordCompletion` / `task.deleteCompletion`
  operations are generated by the Tasks screen, stored in a local
  `task_completion` table, applied from catch-up/pull, and flushed to the
  server. This keeps recurring-task advancement consistent with the web app.

## Sync gaps — what still needs work

- **Read paths route through the local cache when `syncService` is active**.
  `NodeRepository` no longer calls removed `/nodes/*` endpoints on Android/iOS.
  The local queries cover pages, tasks, classes, search, archived nodes,
  breadcrumbs, page content, node/available properties, and favorites.
  Backlinks and class-level property metadata are still not rebuilt locally.
- **Full client-side derived SQLite rebuild**. Only a minimal `node_cache`
  projection and the `task_completion` table are maintained; property tables,
  backlinks, breadcrumbs, trash, and favorites are not rebuilt locally.
- **CRDT text/tree state (Yjs)**. Mobile uses plain `content` arrays, not Yjs
  updates. This is acceptable for simple paragraphs but will not merge edits
  with the web on the same block.
- **Real-time WebSocket sync**. `OfflineSync` polls on app lifecycle; WebSocket
  live sync is not implemented.
- **Task property schemas / options**. The mobile app does not yet emit
  `propertySchema.create` or `classPropertyEdge.create` operations, so task
  status/priority options created on mobile will not have matching option UUIDs
  on the web. For a mobile-only v1 this is fine; cross-device task status
  display needs shared option UUIDs.
- **Task recurrence ops**. `task.setRecurrence` / `task.deleteRecurrence` are
  not yet generated or applied locally, so recurrence rules created on mobile
  do not sync to the server.
- **Move ordering semantics**. Server stores positions as TEXT in
  `node_child_order` and sorts lexicographically; Flutter parses the position
  string as a double and sorts numerically. Multi-digit indices can diverge
  (e.g. `"10"` before `"2"`).
- **Local cache does not consume class/property-schema derived tables**. Server
  snapshots contain `class`, `property_schema`, `class_property_edge`, etc.
  Flutter only restores `node`, `property_value`, and `node_child_order`.
- **`user_favorite` table lacks `actor_id`**. Server favorites are keyed by
  `(actor_id, node_id, workspace_id)`; Flutter's table is keyed by
  `(workspace_id, node_uuid)`. In shared workspaces, favorites from different
  actors would collide locally.
- **Missing op types** are silently ignored on pull: `node.convert`,
  `node.addAlias`, `node.removeAlias`, `node.permanentDelete`,
  `propertySchema.*`, `classPropertyEdge.*`, `class.*`, `nodeView.*`,
  `asset.upload`, `asset.delete`, `activity.record`, `link.click`,
  `share.public.*`, `share.user.*`, `plugin.op`. The mobile cache will become
  stale for tasks, class/property schema changes, views, shares, assets, etc.

## Journal/continuous view navigation

Added Journal as a fourth bottom-navigation destination:
- `MainShellScreen` now has Inbox, Tasks, Journal, Library tabs.
- Journal tab renders the existing `JournalContinuousScreen` (recent daily
  entries, reverse-chronological, pull-to-refresh, today's-journal action).
- Capture FAB moved to `endFloat` to avoid clashing with four nav items.
- Command palette `journals` now switches to the Journal tab instead of
  pushing a separate route.
- `/library` route updated to open at tab index 3.

## Next steps

1. Implement `task.setRecurrence` / `task.deleteRecurrence` intents,
   appliers, and UI so recurring tasks created on mobile sync to the server.
2. Add local derived tables (or in-memory projections) for favorites,
   backlinks, and class/property schemas.
3. Resolve move-ordering semantics: either align with server lexicographic TEXT
   ordering or coordinate a server-side numeric position change.
4. Add `actor_id` to `user_favorite` if shared workspaces are a target use case.
5. Expand local derived-state consumption for `class`, `property_schema`, and
   `class_property_edge` tables from snapshots and catch-up appliers.
6. Manual smoke test against a running server: navigation, capture, tasks,
   share, Quick Settings tile, offline sync.
